1. WHAT IS THIS PROJECT?
--------------------------------------------------------------------------------

Raitha-Bharosa Hub is a native Android application (written in Kotlin with
Jetpack Compose) designed to help Indian farmers make smarter, data-driven
decisions about WHEN to sow their crops.

The core product is a "Sowing Index" — a score from 0 to 100% that combines
soil data, weather conditions, and crop-specific thresholds to tell a farmer
if now is a GREEN (good), AMBER (wait), or RED (do not sow) time to plant.

On top of that, the app has:
  - User authentication (register / login with phone + password)
  - A farmer profile and field setup screen
  - A real-time dashboard showing the sowing index
  - An AI chatbot powered by Groq (LLM API) for farming questions
  - A Krishi Calendar / task scheduler
  - Weather integration (Open-Meteo API)
  - GPS location fetching
  - Bilingual support: English + Kannada

The app is 100% offline-first. All data is stored locally in a Room (SQLite)
database. Internet is only used for weather data and the AI chatbot.

4. HOW THE APP WORKS — SCREEN BY SCREEN
--------------------------------------------------------------------------------

SPLASH SCREEN (SplashScreen.kt)
  - Shows animated logo on launch
  - Checks if user is already logged in via SessionManager
  - Routes to: Dashboard (if logged in) OR Login screen

LOGIN SCREEN (AuthScreens.kt)
  - Phone number + password input
  - Calls AuthViewModel.login() -> AuthRepository -> UserDao
  - On success: saves session in SessionManager, navigates to Dashboard

REGISTER SCREEN (AuthScreens.kt)
  - Name + phone + password fields
  - Hashes password (SHA-256) before storing in Room DB
  - On success: navigates to InputCenter (farmer profile setup)

INPUT CENTER SCREEN (InputCenterScreen.kt)
  - Form for farmer to enter: name, crop type, location, field area, soil type
  - Saves FarmerProfile to Room DB
  - "Get My Location" button fetches GPS coords via FusedLocationProvider

DASHBOARD SCREEN (DashboardScreen.kt)
  - Shows current Sowing Index (0-100%) with color ring: Green/Amber/Red
  - Shows current soil readings (moisture, temperature, NPK, pH)
  - Shows weather card (temperature, humidity, rainfall)
  - "Refresh Data" button generates new simulated sensor data
  - "Schedule Action" button opens task scheduling dialog
  - Bottom navigation bar to other screens
  - DashboardViewModel drives all state via StateFlow

SETTINGS SCREEN (SettingsScreen.kt)
  - Language toggle (English / Kannada)
  - Logout button (clears session, goes back to Login)
  - App version info

PLACEHOLDER SCREENS (PlaceholderScreens.kt)
  - Market Prices, Advisory, Crop Health — UI shells with "coming soon" note
  - Krishi Calendar screen — shows scheduled tasks from Room DB

CHATBOT (ChatBot.kt)
  - Floating action button (bottom-right), draggable anywhere on screen
  - Tap to open/close a chat dialog
  - Sends messages to Groq LLM API (llama-3.3-70b-versatile)
  - Maintains chat history in ChatBotViewModel
  - Farming-context system prompt so answers are agriculture-focused
  - Works on any screen — overlaid on top of all content

5. THE SOWING INDEX ALGORITHM (SowingIndexEngine.kt)
--------------------------------------------------------------------------------

Takes SoilData + WeatherData + crop type and returns a score 0.0–1.0.

FACTOR WEIGHTS:
  - Soil Moisture    25%
  - Temperature      20%
  - NPK Levels       25%  (Nitrogen + Phosphorus + Potassium averaged)
  - Weather          20%  (humidity + rainfall combined)
  - pH               10%

Each factor is scored against CROP-SPECIFIC thresholds:

  SUGARCANE:  Moisture 60-85%, Temp 18-35°C, pH 6.0-7.5
  RAGI:       Moisture 30-70%, Temp 15-32°C, pH 5.5-7.0
  PADDY:      Moisture 70-95%, Temp 18-35°C, pH 5.5-7.0
  COTTON:     Moisture 40-70%, Temp 20-35°C, pH 6.0-8.0
  CORN:       Moisture 50-80%, Temp 18-30°C, pH 5.8-7.0
  (others default to RAGI thresholds)

STATUS INTERPRETATION:
  >= 0.70 -> GREEN  ("Excellent conditions! Optimal sowing window.")
  >= 0.50 -> AMBER  ("Conditions are borderline. Consider waiting...")
  <  0.50 -> RED    ("Conditions are not suitable for sowing.")

The engine also calculates a nextCheckIn time (6h / 24h / 48h) based on status.

6. AI CHATBOT — GROQ INTEGRATION (GrokRepository.kt)
--------------------------------------------------------------------------------

  - Uses Groq's REST API endpoint: https://api.groq.com/openai/v1/chat/completions
  - Model: llama-3.3-70b-versatile
  - API key stored in local.properties as GROQ_API_KEY, injected via BuildConfig
  - System prompt: "You are a helpful agricultural assistant for Indian farmers..."
  - Request/response uses standard OpenAI-compatible chat format
  - ChatBotViewModel keeps message list as StateFlow<List<ChatMessage>>
  - Network call done with Retrofit + OkHttp, parsed with Gson

Flow:
  User types message
    -> ChatBotViewModel.sendMessage()
    -> GrokRepository.chat(messages)
    -> HTTP POST to Groq API
    -> Response parsed, assistant reply added to message list
    -> UI recomposes via StateFlow

9. AUTHENTICATION FLOW (AuthRepository.kt + SessionManager.kt)
--------------------------------------------------------------------------------

REGISTER:
  1. Validate inputs (name, phone, password not blank)
  2. Check if phone already exists in DB (UserDao.getUserByPhone)
  3. Hash password with SHA-256
  4. Insert User into DB
  5. Save userId + username in SharedPreferences (SessionManager)
  6. Return success

LOGIN:
  1. Look up user by phone number
  2. Hash input password and compare with stored hash
  3. On match: save session in SharedPreferences
  4. Return success or error message

SESSION:
  - SessionManager wraps SharedPreferences
  - Stores: userId (Int), username (String), isLoggedIn (Boolean)
  - Checked at splash screen to skip login if session exists
  - Cleared on logout

14. KEY DESIGN DECISIONS
--------------------------------------------------------------------------------

1. OFFLINE FIRST
   All core functionality works without internet. Room DB is the single source
   of truth. Network calls (weather, AI) are supplementary.

2. NO XML LAYOUTS
   100% Jetpack Compose UI. No legacy View system. Faster iteration, better
   state management, less boilerplate.

3. SIMULATED SENSOR DATA
   DataGenerator creates realistic randomized soil/weather readings so the app
   is fully demo-able without real IoT sensors connected.

4. GROQ OVER OPENAI
   Groq's free tier and fast inference made it the practical choice for the
   farming chatbot feature during development/internship.

5. OPEN-METEO FOR WEATHER
   No API key needed. Simple REST API. Works globally including rural India.

6. MANUAL DI (NO HILT/DAGGER)
   Dependencies are manually wired in MainActivity and passed down. Keeps the
   project simple for an internship/MVP scope without DI framework overhead.
